Credit Card Fraud Detection using Unsupervised LearningA Python-based machine learning project that identifies unauthorized, deceptive, or illegal financial transactions using unsupervised learning techniques.  📌 Problem OverviewFraud detection is highly difficult due to several real-world factors:Extreme Class Imbalance: Fraudulent transactions often constitute a tiny fraction (less than 0.2%) of total volume, causing standard classifiers to get trapped in predicting the majority class.  Concept Drift & Evolving Tactics: Fraudsters constantly change their strategies to mimic legitimate user behavior, making historical patterns rapidly obsolete.  Asymmetric Costs: Missing a fraud case (false negative) is far more expensive than falsely flagging a legitimate transaction (false positive).  🎯 Why Unsupervised Learning?While supervised models excel at catching known fraud patterns, they fail catastrophically against novel attack vectors. Unsupervised learning solves this by allowing us to:  Discover anomalies without relying on historical labels.  Flag transactions simply because they deviate significantly from normal baseline behavior.  Adapt flexibly to emerging, unclassified fraud patterns.  📊 Dataset DetailsTotal Records: 284,807 transactions.  Features: 31 columns, including Time, Amount, anonymized variables V1 through V28, and the target Class.  Class Distribution: Class 0 (Normal) makes up 99.8273% of records, while Class 1 (Fraud) makes up only 0.1727% (492 records).  🛠️ Technologies UsedLanguage: Python  Data Manipulation: Pandas, NumPy  Machine Learning: Scikit-Learn (KMeans, IsolationForest, StandardScaler, PCA)  Data Visualization: Matplotlib, Seaborn  🚀 Project Workflow1. Data PreprocessingDuplicated the raw dataset to avoid destructive mutations.  Scaled the Time and Amount columns using StandardScaler to bring them into the same distribution space as the V features.  2. K-Means Clustering ApproachInitialized a K-Means model with 8 clusters.  Calculated the Euclidean distance from each sample point to its assigned centroid for outlier scoring.  Applied a 99.83 percentile threshold to match the expected base rate, successfully flagging 485 anomalous entries.  3. Isolation Forest ExecutionTrained an Isolation Forest model configured with a 0.002 contamination rate to catch roughly 0.2% anomalies.  The model flagged 570 anomalous entries.  4. Evaluation & ComparisonCompared both unsupervised methods, finding 350 shared anomalies.  Evaluated blind predictions against the actual Kaggle ground truth metadata.  K-Means Performance: Showed weak precision and mediocre recall because its reliance on geometric distance caused normal, large-value transactions to skew the metric, resulting in high false positives.  Isolation Forest Performance: Captured a significantly higher ratio of true frauds, proving robust against multi-variable fraud attempts and yielding dramatically superior precision and a stronger recall profile.  🏆 Verdict & ConclusionIsolation Forest is the superior architecture for this domain. In fraud operations, high false positive rates disrupt the end-user experience by locking accounts unnecessarily. Isolation Forest provides the best precision-to-recall balance, maximizing true anomaly isolation while minimizing false positive alerts.  💡 Strategic RecommendationsLayered Deployment Strategy: Deploy the Isolation Forest model as an upstream, real-time filtering heuristic to assign risk probabilities to streaming incoming transaction data payloads.  Semi-Supervised Feedback System: Route transactions identified as high-risk anomalies directly to human forensic analysts so their verification loop can continually update a downstream supervised framework.  Feature Exploration: Incorporate derived behavioral profiles (such as rolling 1-hour transaction volume or geographic distance jumps) to improve the feature space before running unsupervised models.
